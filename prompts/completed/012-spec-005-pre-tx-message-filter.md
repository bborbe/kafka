# Add the pre-transaction batch message filter

<summary>
- The library gains one new decorator that removes messages from a batch before the wrapped handler ever sees them
- A consumer that discards a message for a reason visible in the message bytes can now do so without opening a database transaction for it
- Discarded messages are dropped, surviving messages reach the wrapped handler in one call, in their original order
- A batch where nothing survives is a no-op: the wrapped handler is not called and nil is returned, so the consumer marks the offset and moves on
- The caller's own slice is left untouched, so the consumer's bookkeeping is unaffected
- The wrapped handler's error is returned unchanged, so existing consumer error handling keeps working
- Nothing existing changes: no signature, no default, no interface, no metric
- The contract that the filter must sit outside a transaction-opening handler is stated in the doc comment, where a library reader finds it
</summary>

<objective>
Add `NewMessageHandlerBatchFilter` to package `kafka`: a `MessageHandlerBatch` decorator that drops every message for which a caller-supplied predicate returns true, then calls the wrapped handler once with the survivors in their original order. Composed outside `NewMessageHandlerBatchTxUpdate`, a dropped message never opens a transaction.
</objective>

2. Export exactly this constructor, with this parameter order and this signature:

```go
// NewMessageHandlerBatchFilter returns a MessageHandlerBatch that removes every message for which skip
// returns true before passing the remaining messages, in their original order, to handler in a single call.
func NewMessageHandlerBatchFilter(
	skip func(*sarama.ConsumerMessage) bool,
	handler MessageHandlerBatch,
) MessageHandlerBatch {
	return MessageHandlerBatchFunc(func(ctx context.Context, messages []*sarama.ConsumerMessage) error {
		kept := make([]*sarama.ConsumerMessage, 0, len(messages))
		for _, msg := range messages {
			if skip(msg) {
				continue
			}
			kept = append(kept, msg)
		}
		if len(kept) == 0 {
			return nil
		}
		return handler.ConsumeMessages(ctx, kept)
	})
}
```

The `make([]*sarama.ConsumerMessage, 0, len(messages))` allocation is load-bearing twice: it keeps the `prealloc` linter satisfied, and it is what guarantees the caller's slice and its backing array are never written to. Do not reuse the caller's slice (`messages[:0]` would mutate the backing array) and do not sort or reorder in place.

3. Return the wrapped handler's error unchanged — `return handler.ConsumeMessages(ctx, kept)`, no `errors.Wrapf`, no logging. The consumer's existing error path owns the error; a wrapped error would change what callers match on. `NewMessageHandlerBatchMetrics` in `kafka_message-handler-batch-metrics.go` sets the same precedent; do not wrap it to match the `docs/dod.md` error-handling line.

4. When nothing survives the predicate (including an empty input batch), return `nil` without calling the wrapped handler. Do not call the wrapped handler with an empty slice: the contract is that the wrapped handler is called at most once, and only when at least one message survives.

5. Do not recover panics. A panic raised by `skip` propagates out of `ConsumeMessages` and fails the consumer run — that is the documented behaviour, and swallowing it would hide a broken predicate.

6. The doc comment on `NewMessageHandlerBatchFilter` must state, in addition to the summary line:
   - that the filter must be composed **outside** a transaction-opening handler such as `NewMessageHandlerBatchTxUpdate` to have its effect, because only then is the transaction never opened for a dropped message; composed inside, the output is still correct but the transaction is opened for every batch;
   - that `skip` must be pure and free of side effects and carry no state across calls, because the returned handler is shared by one consumer goroutine per partition and the same predicate is invoked concurrently from all of them;
   - that a message `skip` drops is never seen by the wrapped handler, so a wrong predicate loses the message silently — the filter has no way to detect it.

   Keep it a tight comment (summary line plus those points); do not write an essay.
